---
type: event
id: TEVENT_UNITS_DESTROYED
title: Destroyed, Units, All...
summary: Satisfied while the named house owns no vehicles and no infantry.
valid_values:
  - A house number, as scenario object records define it.
  - If the named house is not in the game, or names a start position that no house holds, the event is always satisfied.
  - If several houses play the named country, the event tests only the first of them the game created.
caveats:
  - Aircraft are not counted, landed or flying. A house with no vehicles and no infantry satisfies the event while it still owns aircraft.
  - Vehicles and infantry with `Insignificant=yes` are not counted, so a house left with only those satisfies the event.
  - A structure with an `UndeploysInto` type counts as a vehicle, unless it is also `ConstructionYard=yes`. A house that still owns such a structure does not satisfy the event.
  - A vehicle or infantry counts from the moment its production starts until it is removed from the game, including while it rides inside a transport. An object that changes owner counts for its new owner.
  - The event puts its tag on the list of the house that owns the trigger, which is offered every frame. The trigger can therefore fire on the first frame the named house owns no vehicles and no infantry. If that house starts the scenario with none, that is the first frame, even if its forces arrive later.
  - Avoid a persistent tag. When a persistent tag fires from the house list, the list offers it again at once, unless it is the first tag on that list. While the trigger stays satisfied, the trigger then fires without end within one frame and the game hangs. A persistent tag that is first on the list fires the trigger once every frame, and once more each time the trigger owner's [base is attacked](/systems/base-attacked/).
  - A semi-persistent tag fires only while exactly one object or map cell holds it, and this event attaches the tag to neither. Use a volatile tag.
