### virtualCallInConstructor (51 findings, 45 distinct)

Harmless. A virtual call in a constructor or destructor runs the version of the class being built, and in every listed case that is the version the author meant.

- Leaf classes (`AircraftClass`, `BuildingClass`, `InfantryClass`, `UnitClass`, `AnimClass`, `TerrainClass`, `WaveClass`, `FoggedObjectClass`, `WWFontClass` and similar) have no derived class, so the call cannot reach an override that was skipped.
- `RawFileClass` (`Set_Name`, `Close`), `GaugeClass` (`Set_Maximum`, `Set_Value`), `LinkClass` (`Add`, `Remove`), `GadgetClass` (`Clear_Focus`) and `ListClass` (`Remove_Scroll_Bar`) have overrides in derived classes. The derived constructors call their own `Set_Name` or `Set_*` explicitly (`CDFileClass`, `CCFileClass`, `SliderClass`), and the derived destructors release their own state first. `Remove_Scroll_Bar` does nothing when called a second time.
- `UIRmlViewClass::~UIRmlViewClass` calls its own `Release`, which no derived view overrides.
- `GaugeClass::GaugeClass` calls `Set_Maximum` and `Set_Value` before `HasThumb` and `IsHorizontal` are set, but those two functions read only `MaxValue` and `CurValue`.

### duplInheritedMember (2,024 findings)

All 2,024 come from 6 data members and 95 distinct member functions. Template instantiations of `DynamicVectorClass` and `TPoint3D` account for most of the rest.

- `SidebarClass::IsToRedraw`, `TabClass::IsToRedraw` (both shadow `PowerClass::IsToRedraw`): each class draws from its own flag, and callers outside the class write the right one with a qualified name (`Map.SidebarClass::IsToRedraw`, `Map.PowerClass::IsToRedraw`). Harmless.
- `BuildingTypeClass::Size` shadows `TechnoTypeClass::Size`. The first is the foundation, the second the passenger size. Cargo code reads the passenger size through `TClass`, so each use gets the meaning it expects. Harmless.
- `VoxelAnimTypeClass::VoxelIndex` shadows the voxel cache in `ObjectTypeClass`. Only `vanim.cpp` reads it, through the derived type. Harmless.
- `UnitClass::Unused1` shadows `TechnoClass::Unused1`. The derived copy was uninitialised; fixed (see above).
- Member functions: the hidden functions are static factories (`From_Name`, `One_Time`), vector and point arithmetic, and thin wrappers (`KeyboardClass::Get`, `Check`, `Clear`). `LogicClass::Submit` hides a non-virtual `LayerClass::Submit`, and `LaserDrawClass::AI` hides `StageClass::AI`; no code calls either through the base type. Harmless.

### code/object.cpp:1784 (was :1748), incorrectLogicOperator

Harmless; the tool is wrong. cppcheck treats `pretag_strength <= 0 || Strength > 0` as a tautology because `pretag_strength` is a copy of `Strength`. Between the copy (`:1740`) and the test, `Tag->Spring` runs trigger actions that can change `Strength`, for example `TACTION_DESTROY_OBJECT` (`taction.cpp:4155`, with a `Take_Damage` call at `taction.cpp:2076`). The test skips the destruction handling when a trigger killed an object that was alive before the triggers ran. The condition is unchanged.
