## Findings that still need a fix

- **Engine SHP shapes are not validated.** `code/shapeset.h:212` (`ShapeSet::Get_Data`) adds a frame's `Data` offset to the file pointer, and the RLE blitters (`code/rlerle.h:99`, `:148`, `:208`) decode until `length` pixels are out, with no end of data. A mod's SHP with a bad `Count`, a `Data` offset past the file or a row that decodes short reads outside the file in `Draw_Shape` (`code/draw.cpp:154`). Suggested fix: in `MixFileClass::Retrieve`, where the entry size is known, check each `*.SHP` once: the records fit, each frame's `Data` is inside the file, a raw frame has `Width * Height` bytes, and each row of a compressed frame has a length of at least 2 that stays in the file and decodes to at least `Width` pixels. I did not add it: a check that is wrong for any real shape would remove that shape from the game, and I could not test against real shapes.
- **VXL span contents are not validated.** The loader now keeps the span tables inside the body, but the per-column offsets in them and the run structure at `DataOffset` are trusted by the drawers (`code/voxlib.cpp`, the `_voxel_draw_*` routines). Suggested fix: walk every column once at load and refuse a model whose runs leave the body. Same caution as above.
- **Other `LCW_Uncomp` callers** still use the unchecked decoder: `code/load.cpp:104` and the VQA code (`code/vqalib/loader.cpp:3072`, `code/vqalib/drawer.cpp:408`, `:751`, `:759`, `:775`, `code/vqalib/task.cpp:366`, `:414`). Their data comes from game files and movies. Suggested fix: give each the compressed size and call `LCW_Uncomp_Checked`.
- **`strtrim` keeps a trailing space** in `code/trim.cpp:73`. The loop tests `*source`, the old pointer into the buffer, instead of `buffer[index]`. `"   ab "` becomes `"ab "` and `"  a   "` becomes `"a "`. Changing it changes how INI values with trailing blanks read, so I left it. Suggested fix: drop the `*source != 0` test.
- **`MapClass::operator[](Cell)`** (`code/map.cpp:494`) computes `x + y * MAP_CELL_H` without checking `x`. A terrain record at `x = -1, y = 1` or `x = 512, y = 0` lands on another cell. It is not a memory error. Suggested fix: refuse a cell with `x` outside `0..MAP_CELL_W - 1`.
- **Options packets lose their tail.** `NetGlobal::Required_Length` counts the 8 bytes of colour and name CRC right after the options text, but `Options.Color` and `NameCRC` sit after all 900 bytes of `Buf` (`code/session.h`). A trimmed packet therefore carries neither, and the receiver reads zero. Nothing reads them but the validator, so there is no effect today.
- **Out-of-range enum loads remain** wherever other code switches on `packet.Command` straight off the wire (`code/netshare.cpp`, `code/ipxmgr.cpp`, `code/netdlg2.cpp`). Only `netglobal.cpp` reads it as an int now.
- **`code/random.cpp:313`** overflows a signed int in the `Random3Class` mix. MSVC wraps it. I met it incidentally; no test covers it.
- **`code/sha.cpp`, `code/int.cpp` and the RSA code assume a 32-bit `long`.** They give wrong results or write past a `long[5]` on Linux, so the harness could not run them. On Windows they are not affected.

## `ColorRGB`

The job names `ColorRGB` in spawn.ini as new. `origin/modern` has no reader for it: it is not in `code/spawnerconfig.cpp` or anywhere else under `code/`, `manual/` or `docs/`, and no local branch adds it. The spawn.ini seeds carry `ColorRGB=` lines in `[Settings]` and `[Other1]` and the dictionary holds the key, so the harness reads them as unknown keys now and exercises the reader once it exists. Add range checks (0 to 255 per channel, exactly three values) with the reader.

## Ran

All ten tests pass, 18 s in all.
- A second configuration with `-DOPENTS_FUZZ_SANITIZE=OFF` for `fuzz_csf`, `fuzz_lcw` and `fuzz_net`: builds and passes.
- Longer runs of every test with seeds 101 to 103 and 12,000 to 300,000 mutated inputs each (a few million inputs in all): no failures after the fixes. `fuzz_ini`, `fuzz_spawn` and `fuzz_lcw` also ran on other seeds while I wrote them.
- Existing contract tests built the same way, as a check that the fixes keep their results: `tests/lcwblock` (0 failures), `tests/csf` (all checks pass), `tests/netpacket` (all checks pass, with `-fno-sanitize=enum` because the test itself loads an out-of-range enum), `tests/spawner` (all but the two checks about Windows paths and drive letters, which depend on `std::filesystem` on Windows).

I discarded the regenerated `manual/data/*.yaml` each time, including `ini-keys.yaml`, which `update` regenerates with 153 lines that do not come from this branch.
