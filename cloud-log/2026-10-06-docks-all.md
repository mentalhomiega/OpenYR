Branch `cloud/docks-all-2026-10-06`, begun from `origin/cloud/docks-2026-10-06`. The owner decided that a building with `NumberOfDocks` above 1 acts on every dock for repair, hospital, armory, capture and sell. The finding numbers are those of `cloud-log/2026-10-06-docks.md`. ## Re-read

- Save game and CRC: no field was added; `Serialize` and `Compute_CRC` are untouched. `Dock_Free_Aircraft` is a non-virtual private member.
- Empty slots: every loop skips a null `Link(slot)`; no code reads `Contact_With_Whom()` as non-null after the change, except where the old code did and a test of slot 0 or `In_Radio_Contact` preceded it (see below).
- Removed objects: the capture loop works on a snapshot and skips a docker whose slot a trigger emptied; the sell loop and the repair loops read `Link(slot)` fresh for each index and use the object only until `Sell_Back` or `OVER_OUT`.

## Unsure or left

- Behaviour with several docks that I could not check against the game: a repair bay with several customers shares one `Status` and one stage timer. When one object finishes or lacks credits, the state falls to IDLE and the others are stepped at the IDLE check rate (14 frames) until a paid step returns it to DURING (15 frames), so their step spacing differs slightly from the single-customer cycle. The state is not saved per dock because adding a field would change saves and CRC.
- Selling: one sell order sells every parked object in a single pass. The alternative, one object per order, would need the player to order the sale again. The owner should say which is wanted.
- `RADIO_ARE_REFINERY` (`:607`) refuses a repair bay while `In_Radio_Contact()` is true for any slot, so a multi-dock repair bay refuses depot queries while one dock is held. This is outside the seven findings and was not changed.
- A hospital or armory still treats one infantry at a time whatever `NumberOfDocks` is: the cargo holds one object and `RADIO_CAN_LOAD` refuses while the mission is `MISSION_REPAIR`. Only the docking reply was changed.
- `Detach_All` (`:7127`, `:7131`): the `!all` branch calls `House->Is_Ally(Contact_With_Whom())` after `In_Radio_Contact()`, which is a null read when only slot 1 is held, and both branches send `RADIO_OVER_OUT` to slot 0 only. Other uses of `Contact_With_Whom()` after `In_Radio_Contact()` have the same shape: `Draw_Extras` (`:973`, the factory door, which uses one dock). A loop over the slots would fix `Detach_All`.
- `Do_MISSION_REPAIR` repairs an object only within a quarter of a cell of the structure's center, so each `DockingOffsetN=` must stay that close; the manual says so.
