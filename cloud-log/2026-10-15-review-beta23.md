# Review of the Beta 23 changes (33ea7c86..d375ab28)

Branch: `cloud/review-beta23-2026-10-15`, started from `origin/modern` (4d36e67d). The worktree I was given sat on another line of history, so I branched from `origin/modern` and not from the checked-out HEAD.

## Commits

| Commit | What it does |
| --- | --- |
| Give no voxel highlight to faces turned away from the viewer | `Voxel_Specular_Term` (new `code/voxshade.h`) returns no highlight for a surface whose normal points away from the halfway direction. With `VoxelSpecularStrength` between 0 and 0.5 the old formula `h / (s - h*s + h)` turned positive again for faces with `h` below `-s / (1 - s)`, so back faces took a bright highlight. New `voxelshade` test, key page note and change record. |
| Add the structure recoil keys to the INI key catalog | `manage.py update` output that the recoil commit (29bd804f) did not include: the eight `Turret*`/`Barrel*` keys and `TurretRecoil` in `manual/data/ini-keys.yaml`. |
| Keep a voxel shade row inside the palette for any VoxelShadeScale | `Voxel_Shade_Row` holds the row to 0..31 and gives row 0 for NaN. `VoxelShadeScale=nan` (which the INI parser accepts) made the row undefined, and the drawers index the palette lookup with it unchecked. Test, key page note and change record. |
| Read OPENTS.INI comments after a value as the game does | The launcher's `Ini_Value` only skipped whole-line comments. The game cuts a line at the first `;`, so `Check=no ; skip` still checked for updates, and `DataDirectory=C:\RA2 ; mine` passed the comment to the setup as part of the path. Four new launcher checks; `docs/LAUNCHER.md` updated. |
| Correct the note on a -SPAWN game whose scenario fails to load | See finding 1 below. Comment and change record only. |

## Findings fixed above

1. `-SPAWN` scenario failure (`code/init.cpp`, `Select_Game`): the change record said the game no longer starts the match on an empty map. It never did. The old path was `goto restart`, which reaches `Spawner_Prepare`, and that answers false once `SpawnConsumed` is set, so the game already exited. The commit's only effect is that the menu music no longer restarts before the exit. I corrected the comment and the record; the code is unchanged.
2. The recoil keys were missing from `ini-keys.yaml` (second commit).

## Findings still open

| Where | Case | Suggested fix |
| --- | --- | --- |
| `code/building.cpp` `BuildingRecoilState::Fire` | A shot fired while the part is still compressing, holding or recovering adds a whole new `Travel` to `TravelSoFar`. With `BarrelTravel=8`, compress 3, hold 3, recover 40, a shot 10 frames after the last one moves the barrel back about 15, past the stated 8, and the recovery then ends with a snap to 0. Only a rate of fire under the 46-frame cycle reaches it. I could not tell whether gamemd does the same, so I left it. | If gamemd clamps, compress only the distance left to `Travel`. |
| `code/building.cpp` `Draw_Extras`, barrel-only branch (`AuxVoxel` null, `AuxVoxel2` set) | The barrel drawn alone ignores `BarrelRecoil`, so `TurretRecoil=yes` has no effect on such a structure. | Apply `Translate_X(-BarrelRecoil.TravelSoFar)` there if gamemd does. |
| `tests/cellrecords/cellrecords.cpp` `Test_Cut_At_Block_Edge` | The comment says no block edge falls on a record boundary. A version 4 record is 10 bytes, so the fifth block edge (40960 bytes) does. A pack cut there reads as whole, as it does in gamemd. | Fix the comment; the behaviour cannot be detected. |
| `tools/setup/setup_core.cpp` `Install_Package` | The cleanup of files the earlier build wrote runs before `UninstallerName` is added to `written`. An update deletes `Uninstall OpenYR.exe` and then writes it again. If the second write fails, the uninstaller is gone while the shortcut and registry entry still point at it. | Skip `UninstallerName` in the cleanup when `UninstallerSource` is set. |
| `tools/launcher/launcher_main.cpp` `Run_Update` | The copy ends with `Schedule_Folder_Removal(self_folder)`. Run by hand from the install folder with `/UPDATE=...`, it would remove the install folder. The docs say not to pass these switches, but nothing stops it. Job B's area. | Refuse to run when `self_folder` is `options.Folder` or inside it. |
| `tools/launcher/launcher_core.cpp` `Parse_Value` | `std::strchr("+-.eE0123456789", text[end])` is non-null for a NUL byte, so a NUL inside a number is consumed and `1<NUL>` parses as 1. Job B's area. | Stop the number at `'\0'`. |
| `tools/launcher/launcher_core.cpp` `Ini_Value` | The game takes the last value of a repeated key and ignores a key with an empty value. The launcher takes the first and accepts an empty one. A test asserts first-wins, so I left it and documented it. | Take the last non-empty match, and change the test. |
| `tools/launcher/launcher_main.cpp` `Run_Launcher` | A client that starts `OpenYR.exe -SPAWN` while a newer beta exists gets a modal question and waits for a click. | Skip the update check when the game arguments hold `-SPAWN`. |
| `manual` change record for 29bd804f | `TurretTravel` and the other keys are documented in leptons, but the code feeds the value to `Matrix3D::Translate_X` unscaled, while the neighbouring `TurretOffset` is divided by 8 before it reaches the matrix. Whether the keys are leptons or matrix units cannot be told from the code; they match the old fixed offset only at the default of 2. | Confirm the unit against gamemd and divide by 8 if the keys are in leptons. |

## Checked and found sound

- `code/cellrecords.h` and `Read_Binary_4/5`: the new reader matches the old field order and sizes; the LZO straw reports a cut header, block or record as damage. The `cellrecords` test passes under g++ (7 of 7).
- Recoil save and sync: `BuildingRecoilState` is draw-only and not saved, and the building type's new fields are in `Serialize` and `Compute_CRC` with `REVISION` bumped to 69. The new `[AudioVisual]` voxel keys are read at start-up, before a save loads, so leaving them out of `RulesClass::Serialize` is safe.
- Specular and shade code: with the fix, the lookup row stays in 0..31 and the three neutral entries match between the diffuse and highlight tables.
- `setup_core.cpp`, `setup_payload.cpp`, `setup_find.cpp` and the launcher's feed, decision and process code: read for logic errors beyond the items above and found none. Security (zip names, uninstall, download checks, DLL search order) is job B's.
