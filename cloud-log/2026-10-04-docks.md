## Still open

These send untargeted messages or act on slot 0 at a multi-dock building. Each needs the owner's answer to the carried question of whether such a building should act on every slot; with one dock all of them behave as before.

- `code/building.cpp:562-566` (`RADIO_DOCKING`): the repair-bay `needs_to_move` test measures the first dock's object, not the sender. Changing it would also change a single-dock pad that sets both `Helipad=yes` and `UnitRepair=yes` while another aircraft holds its dock.
- `code/building.cpp:529-540`: hospital and armory replies use slot 0. They take one object at a time unless a mod sets `NumberOfDocks`.
- `code/building.cpp:4652-4666` (capture): only the first dock's object is captured with the structure.
- `code/building.cpp:5019-5041` and `:5057-5062` (`Mission_Guard` IDLE): only the first dock's object can start a repair or rearm mission.
- `code/building.cpp:5227-5233` (sell): a repair bay sells only the object on its first dock.
- `Mission_Repair` for `UnitRepair=yes` (`code/building.cpp:5947` on): repairs slot 0 only. Serving every dock, as the rearm loop at `:6175` does, would be a feature change.
- `Place_Free_Aircraft` stands a pad's free aircraft at the center; `Exit_Object` moves a built aircraft onto its dock. Moving the free aircraft too would match them; the manual now states the current behaviour.
