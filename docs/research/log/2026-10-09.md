## Main finding

The Ares table was built from the `master` branch of the Ares documentation repository, which holds a 2012 snapshot of 140 pages. The documentation the Ares team publishes is the `gh-pages` branch (December 2020), with 404 pages. This explains why a Mental Omega scan found so many unknown Ares keys. All Ares rows now come from the 2020 sources.

## Corrections to the Phobos table

The Phobos source settled the spelling questions from the last session:

- `IsDestroyableObstacle`, `Sidebar.GDIPositions`, `BunkerROFMultMultiplier` and `CrateOnlyOnLand` are read as the table spelled them.
- `AutoDeath.PlayerMoney.Max` and `AutoDeath.PlayerMoney.Min` are the real names; the table said `PlayerMoneyLessThan` and `PlayerMoneyMoreThan` and was corrected.
- `[General] AttachEffects.AttachOnOwnerChange` is plural in the source and the per-country key is singular. The old spellings `AffectTargets`, `RevengeWeapon.AffectsHouses` and `ReflectDamage.AffectsHouses` are still read.
- `ElectricAssaultLevel` (default 1) is what each attacker adds to a building's overpower total. `Overpower.ChargeWeapon` (default 1) is the total that switches weapons. `Overpower.KeepOnline` (default 2) is the total that keeps the building online in low power. A negative value disables each.
- `InheritArmor.Disallowed` is ignored when `InheritArmor.Allowed` is empty. A shield `Strength` of 0 or less creates no shield. `SelfHealing` and `Respawn` values from -1.0 to 1.0 are fractions of Strength; other values are whole points.

The Ares table dropped `FactoryOwners.HasAllPlans`; the current name is `FactoryOwners.Permanent`.

## Specs

Five specs were added in the format `specs/README.md` sets, in `priorities.md` order and skipping groups that already had one: `phobos-per-type-rules.md` (item 3), `phobos-weapon-selection.md` (item 5), `phobos-attached-effects.md` (item 6), `phobos-shields.md` (item 7) and `phobos-autodeath-convert-animunit.md` (item 8). Each was drafted by a helper agent from the Phobos documentation and source, then checked for the required headings, copied code (none; the only code blocks are INI examples), and engine names and files (all exist in `code/`). The test plans were not run, and their expected numbers come from reading the source.

Points the specs raise for the owner:

- `TechnoClass::Greatest_Threat_Scan` in `code/techno.cpp` never updates `bestval` in its ring loops, so a ring scan returns the last candidate it reaches instead of the best one. The manual says the same. Phobos's `ExtraThreat` and `DisableOveroptimizationInTargeting` assume the best score wins. This may be inherited behaviour; test 1 of `phobos-weapon-selection.md` settles it.
- Placing the Phobos shield step at the start of `TechnoClass::Take_Damage` lets shields absorb hits that stock code ignores, such as radiation, and the residue maths seems to apply distance falloff twice on the breaking hit (`phobos-shields.md`, owner decisions).
- Phobos `Convert.Health.AbovePercent` looks like it never converts when set alone, and Phobos's own type-conversion path is bypassed when Ares is loaded, so only the fallback path could be specified.
- The Phobos type class `AttachEffectTypeClass` has the same name as the engine's Ares struct. Whether Phobos effects extend `code/attacheffect.cpp` or live beside it is an open question in `phobos-attached-effects.md`.
- Phobos's bunker damage hook seems to fall back to `OccupyDamageMultiplier` instead of `BunkerDamageMultiplier`.

## Unclear in the sources

- No Ares page defines `Foundation.*` or `FoundationOutline.*`; the foundation page only points to an external generator. Mental Omega uses them heavily, so their meaning must come from observed behaviour. `ForceShield.Modifier` is the only `ForceShield.*` key the Ares pages define.
- The Ares superweapon pages disagree on the `SW.RangeMinimum` default for EMPulse (0.0 on its page, -1.0 on the range page). `SW.ShowCameo` and `SW.ManualFire` are said to be ignored when `SW.AutoFire=no`, which is the default. Map actions 92 and 93 control the Firestorm but the page does not say which does what.
- The Ares pages for self-healing and survivors contradict each other about which tags override which. The `Experience.AirstrikeModifier` page names a tag it never defines; the row assumes `Experience.FromAirstrike`.
- `DebugKeysEnabled` defaults to true in the Phobos code. `CustomGS<n>.DefaultDelay` rejects 0. Move to cell uses 128 on maps with `NewINIFormat` below 4. The bunker damage fallback uses `OccupyDamageMultiplier`. The Phobos Notes in the agent files give file and line for each; they were not copied into the table.
- The anchor `minimap-color-customization-1` on a Phobos Tiberium row is a guess, because two headings share the title.
- The Interop DLL exports (13 rows in Miscellaneous) are not INI keys.
